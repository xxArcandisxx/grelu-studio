# gReLU Studio — current codebase feature inventory

Audit date: 2026-11-23 UTC. Static inspection only: no app imports, HTTP requests, browser interaction, inference, training, dependency installation, or downloads were performed for this audit. The only intended writes are these seven new audit reports. Existing evidence, including the untracked browser setup plan, is retained.

## Scope and counting

There are **30 feature groups: 22 tool workflows and 8 supporting website capabilities**. Batch sequence prediction and shuffled baselines are subfeatures of F01; regression/binary evaluation are subfeatures of F17. Counts are not route, button, or scientific-validation counts. **27 groups are complete within their explicitly bounded local scope; 3 are partial against their broader advertised capability (F05, F22, F28).** Completeness is a source-inspection judgment, not a new successful execution claim. Layer freezing, genome-coordinate upload, and other missing capabilities are listed separately, not counted as implemented groups.

See [coverage](EXISTING_TEST_COVERAGE.md), [resources](DATASET_RESOURCE_INVENTORY.md), [input mapping](FEATURE_DATASET_MAPPING.md), [training](TRAINING_FINETUNING_STATUS.md), [manual plan](MANUAL_BROWSER_TEST_PLAN.md), and [gaps](GAPS_AND_RECOMMENDATIONS.md).

## Model and execution conventions

- **D:** built-in compact CNN, normally 200 bp, three tasks `task_0..2`, seeded random weights. It really computes numerical outputs but is **not pretrained biological evidence**. Defined in [studio_web.py](studio_web.py), `MODELS`; built by [core/models.py](core/models.py), `_build_demo_model`/`load_model`.
- **H:** optional startup `human` checkpoint, configured through `GRELU_HUMAN_CHECKPOINT`; launcher seeks a cache-only pinned GM12878 model, revision `9f2aaba3e04c5b7324a239c7af53fc4732cb2c3e`, SHA-256 `f266b296f49b4e97e3ac52e94594da0aaae1d467778ea58b421e1ee7c4482bea`. Its authoritative workflow length is 2,114 bp, task `ENCFF093VXI`, pooled native output `(N,1,1)`. Sources: [run_studio.sh](run_studio.sh), [identity fixture](Testing/testing-phase-2/input-output/fixtures/model_identity.json), [Gate 6 summary](Testing/testing-phase-2/input-output/gate-6/STEP_1_SUMMARY.md). A single pooled value must not be described as a spatial genomic track or calibrated probability.
- **L:** registered checkpoint or Studio-trained model with discoverable native input length and compatible output/architecture. [model_registry.py](model_registry.py), `sync_models`; [core/model_lengths.py](core/model_lengths.py), `required_length`; [core/models.py](core/models.py), `load_model`. Catalog identifiers are not aliases to H and are disabled until installed. No claim that all catalog architectures work.
- All website model workflows use CPU and the shared `inference_lock`; trained/installed job work shares that lock. Predictions are genuine forward calls; attribution uses gradients; motif simulation replaces sequence segments and runs predictions, rather than fabricating outcomes. No numerical workflow below merely replays a saved score unless expressly described as a snapshot view.
- `model_choices()` can deserialize checkpoint metadata. `/api/model-info` and inspector can instantiate a model; models without task metadata may run an all-N shape probe. Thus opening certain advanced pages can trigger model metadata/shape work through JavaScript even before Run. Sources: [studio_services.py](studio_services.py), `_metadata`; [core/models.py](core/models.py), `load_model`; [static/advanced.js](static/advanced.js), `loadTracks`.
- Global request cap: 600,000 bytes. Standard batch parser: up to 12 unique FASTA identifiers, A/C/G/T/N, at most 200,000 bases per record. Most model pages require exact native length. Only pairwise comparison with D expressly permits shorter inputs and records center-N-padding. Sources: [studio_web.py](studio_web.py), `MAX_CONTENT_LENGTH`/`compare`; [core/dna_inputs.py](core/dna_inputs.py), `parse_records`; [workbench.py](workbench.py), `analyze`.

## Not implemented as current website features

- BED validation/extraction page: removed. [test-inputs/README.md](test-inputs/README.md) expressly retains the former fixture for future work; [research_views.py](research_views.py) `PAGES` has no `bed`. [bed_to_fasta.py](bed_to_fasta.py) is a separate network-enabled CLI helper, not a website capability.
- VCF or genomic-coordinate variant upload/liftover: engine VEP has optional reference-context code, but website validates sequence-column CSV only; pair API explicitly rejects coordinate/assembly fields. Do not promote engine-only support to UI support.
- General dataset ingestion/catalog/split export, full-genome sequence browser, bigWig uploads, variant genotype calling, independent epistasis estimates, TF-MoDISco, integrated gradients/SHAP, layer freezing, architecture customization, optimizer-resume checkpoints, server PDF export, and SMTP delivery have no wired current implementation identified.
- No current workflow is a numerical-results mock. Synthetic sequence generation and randomized-weight diagnostic models are explicitly different from fabricated result values; saved-detail views intentionally render stored outputs.
