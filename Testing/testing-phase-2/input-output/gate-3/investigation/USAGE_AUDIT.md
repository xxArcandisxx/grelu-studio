# Complete current website usage audit

The reproducible inventory is [usage-audit.json](usage-audit.json), generated by
`python3 Testing/testing-phase-2/input-output/gate-3/investigation/audit_usage.py`.
It scans 101 source/configuration files, including ignored and hidden files
within the application source scope, using `rg --files --hidden --no-ignore`.
Every included file has a SHA-256. Python files are also parsed with AST; there
are no parse failures.

The scan covers root modules, `core/`, `workflows/`, `src/`, `static/`,
`templates/`, scripts, tests, shell launchers and source configuration. It
excludes `.git`, the virtualenv (separately inspected below), private agent/cloud
configuration, bytecode, runtime databases/uploads/outputs, testing artifacts,
input fixtures and downloaded datasets. The exact directories and extensions
are recorded in JSON. Those are data/environment exclusions, not unsearched
website implementations. The original Gate 3 tests intentionally call the
inverse functions and are archived under excluded `Testing/`; the new optional
compatibility test does too. Neither is an application workflow.

There are **zero website references** to `one_hot_to_strings`,
`one_hot_to_indices`, `indices_to_strings`, or the generic `convert_input_type`
dispatcher. The import inventory also rules out an aliased import of those
functions or their containing format module. All dynamic lookup/import calls
were reviewed: they concern image flags, Torch device support, checkpoint
metadata, NumPy safe metadata dtypes, deterministic Python random examples and
test dispatch. None dynamically constructs an inverse call. No `eval`/`exec`
path to the inverse was found.

## Indirect library usage

All direct gReLU imports in the website are inventoried with paths and lines.
The reached third-party entry points were inspected beyond a text-only absence
check:

- `grelu.lightning.LightningModel.predict_on_seqs` calls `strings_to_one_hot`,
  device transfer and forward. `format_input` and `forward` format a tensor,
  invoke the architecture, activation and prediction transform. They do not
  decode DNA. The GM12878 `DilatedConvModel` implementation under `grelu/model/`
  contains no affected inverse/dispatcher calls.
- `LightningModel.load_from_checkpoint` and `grelu.resources.load_model` load
  model architecture/state. Resource listing/model-info/dataset/base-model
  functions handle metadata and do not invoke the inverse. No website code uses
  `predict_on_dataset` or the library interpretation/design routines.
- `core/grelu_api.py` can import numerical `Aggregate` and `Specificity`
  transforms; their installed module has no inverse/dispatcher call. Helpers
  `parse_evolve`, `ism_to_matrix`, and `attribution_to_matrix` parse already
  returned strings/arrays; they do not invoke gReLU design or interpretation.
  `parse_evolve` has no caller in the scanned source.
- Whole-library search results are saved in `library_inverse_and_dispatcher_callsites`
  in the audit JSON. Native gReLU design and some dataset/interpretation paths
  **do** use `convert_input_type(..., 'strings')`, which can call the faulty
  inverse. Those are external capabilities not reached by the current website
  implementations above. Importing dataset definitions in Lightning is not an
  execution of their decoding paths.

Source-level review is an impact audit of the current code and pinned model,
not a runtime certification of all later inference branches or future models.
Earlier Gate 3 PARTIAL/NOT TESTED workflow classifications remain intact.
Adding native design/dataset/interpretation features would require a fresh
usage review and passing compatibility tests for the representations used.

## Production impact

No current website workflow reaches the faulty inverse, so no production
workaround or dependency patch is appropriate for this finding. No website code,
installed package file or pretrained weight was changed during this investigation.
The dependency defect remains reproducible and recorded as an external
compatibility limitation; the optional test exits nonzero while it persists.
